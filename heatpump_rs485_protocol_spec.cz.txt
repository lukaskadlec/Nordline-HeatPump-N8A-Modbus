1. KONFIGURACE FYZICKÉ A LINKOVÉ VRSTVY
================================================================================
Rozhraní sběrnice  : RS-485 (dvoudrát, Half-Duplex, diferenciální linky A/B)
Port zařízení Linux: /dev/ttyUSB-TC (USB-RS485 převodník)
Přenosová rychlost : 9600 bps
Datové bity        : 8
Parita             : Žádná (None - N)
Stop bity          : 1
Řízení toku        : Žádné (None)
Standard rámce     : Modbus RTU
Pořadí bajtů       : Big-Endian (MSB nejprve) pro 16bitová slova registrů
Algoritmus CRC     : Modbus CRC-16 (Polynom: 0xA001, Init: 0xFFFF, Low-Bajt první)

Výpočet CRC v JavaScriptu (Referenční kód):
-------------------------------------------
function calculateCRC(buf, length) {
    let crc = 0xFFFF;
    for (let pos = 0; pos < length; pos++) {
        crc ^= buf[pos];
        for (let i = 8; i !== 0; i--) {
            if ((crc & 0x0001) !== 0) {
                crc = (crc >> 1) ^ 0xA001;
            } else {
                crc >>= 1;
            }
        }
    }
    return crc; // low bajt: crc & 0xFF, high bajt: (crc >> 8) & 0xFF
}

2. ARCHITEKTURA SYSTÉMU A ÚČASTNÍCI NA SBĚRNICI
================================================================================
Hlavní řídicí deska tepelného čerpadla (PC8002 PCB) funguje jako Modbus MASTER.
Všechny ostatní připojené moduly vystupují jako Modbus SLAVE jednotky.

Adresy zařízení / Slave:
------------------------
- Adresa 0x00 (0)  : Modbus Broadcast (Vysílá Master všem jednotkám; žádný Slave neodpovídá)
- Adresa 0x01 (1)  : Hlavní ovládací panel / modul nástěnného LCD displeje
- Adresa 0x02 (2)  : Sekundární ovládací panel / rozšiřující displej (volitelný/dotazovaný)
- Adresa 0x04 (4)  : Pohon kompresoru / řídicí deska invertoru 1
- Adresa 0x05 (5)  : Motor ventilátoru / deska pohonu 2

Topologie:
----------
  +-----------------------------------------------------------+
  |                   RS-485 Sběrnice (9600 8N1)              |
  +----+-------------+-----------------+-------------+--------+
       |             |                 |             |
+------+-----+ +-----+------+    +-----+------+ +----+-------+
| Hlavní PCB | | LCD displej|    | Invertor 1 | | Invertor 2 |
|  čerpadla  | |  (Slave 1) |    |  (Slave 4) | |  (Slave 5) |
|  [MASTER]  | +------------+    +------------+ +------------+
+------------+


================================================================================
3. PŘEHLED CYKLICKÉ KOMUNIKACE (POLLINGOVÝ CYKLUS)
================================================================================
Řídicí deska (Master) provozuje aktivní dotazovací smyčku s periodou přibližně 1 sekunda.
Běžná sekvence probíhá v tomto pořadí:

1. Všesměrové vysílání stavu část A (Adresa 0, FC 16, Reg 2001, 90 reg. / 180 bajtů)
2. Všesměrové vysílání stavu část B (Adresa 0, FC 16, Reg 2091, 90 reg. / 180 bajtů)
3. Dotaz na LCD displej (Adresa 1, FC 03, Reg 3001, 21 reg. / 42 bajtů)
   -> LCD odpovídá paketem heartbeat + příznak stavu/události + reálný čas RTC.
4. Pokud LCD nahlásí příznak události / změny v Registru 3011:
   - Příznak 0x0002 : Spustí synchronizaci Bloku 1 nastavení (Reg 1001..1090)
   - Příznak 0x0004 : Spustí synchronizaci Bloku 2 nastavení (Reg 1091..1180)
   - Příznak 0x0008 : Spustí synchronizaci Bloku 3 nastavení (Reg 1181..1270)
   - Příznak 0x8000 : Kompletní inicializace / plná synchronizace všech 3 bloků (Reg 1001..1270)
   -> Master provede odpovídající synchronizační handshake.
5. Dotaz na sekundární displej, je-li konfigurován (Adresa 2, FC 03, Reg 3001, 21 reg.).
6. Dotaz na Invertor 1 (Adresa 4, FC 03, Reg 1011, 14 reg.) -> Invertor 1 odpovídá (28 bajtů).
7. Příkaz pro Invertor 1 (Adresa 4, FC 16, cílová frekvence).
8. Dotaz na Invertor 2 (Adresa 5, FC 03, Reg 1011, 14 reg.) -> Invertor 2 odpovídá (28 bajtů).

4. PODROBNÁ SPECIFIKACE ZPRÁV

--------------------------------------------------------------------------------
4.1 Všesměrové vysílání Master část A (Stav a telemetrie)
--------------------------------------------------------------------------------
Směr      : Master -> Všesměrové vysílání Broadcast (Odezva se neočekává)
Funkce    : Modbus FC 16 (0x10) - Zápis více registrů (Write Multiple Registers)
Záhlaví   : [00, 16, 07, 209, 00, 90, 180] -> [0x00, 0x10, 0x07, 0xD1, 0x00, 0x5A, 0xB4]
            - Slave adresa     : 0 (Broadcast)
            - Funkční kód      : 16 (0x10)
            - Počáteční registr: 2001 (0x07D1)
            - Počet registrů   : 90 (0x005A)
            - Počet bajtů      : 180 (0xB4)
Data      : 180 bajtů živé telemetrie (teploty, tlaky, relé, EEV, elektrické veličiny).
CRC       : 2 bajty Modbus CRC-16.
Celk.délka: 189 bajtů.

--------------------------------------------------------------------------------
4.2 Všesměrové vysílání Master část B (Řízení systému a synchronizace)
--------------------------------------------------------------------------------
Směr      : Master -> Všesměrové vysílání Broadcast (Odezva se neočekává)
Funkce    : Modbus FC 16 (0x10) - Zápis více registrů (Write Multiple Registers)
Záhlaví   : [00, 16, 08, 43, 00, 90, 180] -> [0x00, 0x10, 0x08, 0x2B, 0x00, 0x5A, 0xB4]
            - Slave adresa     : 0 (Broadcast)
            - Funkční kód      : 16 (0x10)
            - Počáteční registr: 2091 (0x082B)
            - Počet registrů   : 90 (0x005A)
            - Počet bajtů      : 180 (0xB4)
Klíčové offsety v rámci bufferu:
- Offset 25 (2 bajty) : Potvrzovací hodnota registru 2091
- Offset 33 (2 bajty) : Konstanta 15 (0x000F)
- Offset 35 (2 bajty) : Konstanta 738 (0x02E2)
- Offset 37 (2 bajty) : Přepínací stav (0 nebo 1), mění se každých několik minut
- Offset 39 (2 bajty) : Magické synchronizační slovo: 0x5AA5 (23205 dec)

--------------------------------------------------------------------------------
4.3 Dotazování na LCD displej a heartbeat (Slave 1)
--------------------------------------------------------------------------------
Směr      : Master -> Slave 1 (Dotaz / Poll)
Požadavek : [01, 03, 11, 185, 00, 21, 87, 196] -> [0x01, 0x03, 0x0B, 0xB9, 0x00, 0x15, 0x57, 0xC4]
            - Slave ID         : 1
            - Funkční kód      : 3 (Read Holding Registers)
            - Počáteční adresa : 3001 (0x0BB9)
            - Počet registrů   : 21 (0x0015)
            - CRC-16           : 0x57 0xC4

Směr      : Slave 1 -> Master (Odpověď)
Formát    : [01, 03, 42, <42 datových bajtů>, <CRC_LOW>, <CRC_HIGH>] (Celkem 47 bajtů)
            - Slave ID         : 1
            - Funkční kód      : 3
            - Počet bajtů      : 42 (0x2A = 21 registrů * 2)
            - Bajty [3..22]    : Řídicí a stavové registry (Reg 3001..3010), většinou 0x00.
            - Offset 23-24     : Registr události / spouštěče (Reg 3011, Big-Endian):
                                 * 0x0000 = Klidový stav (Idle), žádná změna.
                                 * 0x0002 = Změna Bloku 1 nastavení (Reg 1001..1090).
                                 * 0x0004 = Změna Bloku 2 nastavení (Reg 1091..1180).
                                 * 0x0008 = Změna Bloku 3 nastavení (Reg 1181..1270).
                                 * 0x8000 = Spuštění plné inicializace / resynchronizace
                                            (bajt 23 = 128 / 0x80, bajt 24 = 0).
            - Bajty [35..44]   : Reálný čas (RTC) vysílaný z LCD displeje:
                                 * Offset 35-36: Rok % 100 (např. 26 pro rok 2026)
                                 * Offset 37-38: Měsíc (1-12)
                                 * Offset 39-40: Den v měsíci (1-31)
                                 * Offset 41-42: Hodina (0-23)
                                 * Offset 43-44: Minuta (0-59)

--------------------------------------------------------------------------------
4.4 Handshake synchronizace nastavení (Displej -> Master)
--------------------------------------------------------------------------------
Při úpravě parametrů v konkrétním bloku Registr 3011 uvědomí Master:

- Blok 1 (Příznak 0x0002): Master synchronizuje 90 registrů od adresy 1001 (0x03E9).
- Blok 2 (Příznak 0x0004): Master synchronizuje 90 registrů od adresy 1091 (0x0443).
- Blok 3 (Příznak 0x0008): Master synchronizuje 90 registrů od adresy 1181 (0x049D).

Průběh synchronizace jednoho bloku:
1. LCD nastaví příznak (0x0002, 0x0004 nebo 0x0008) v Registru 3011 při odpovědi na dotaz.
2. Master si vyžádá data přes FC 03 Read NEBO zapíše data přes FC 16 Write.
3. LCD přenese nebo potvrdí 180 bajtů konfiguračních dat.
4. Master odešle FC 16 pro vymazání Registru 3011: [01, 16, 0B, C3, 00, 01, 02, 00, 00, 0D, A3].
5. LCD potvrdí zápis ozvěnou FC 16: [01, 16, 0B, C3, 00, 01, F3, D1].
Handshake je dokončen; sběrnice se vrací do klidového dotazování 1 Hz.

--------------------------------------------------------------------------------
4.5 Handshake úplné inicializace systému (Flag 128 / 0x8000 kompletní vyčtení)
--------------------------------------------------------------------------------
Když se LCD ovladač zapne, restartuje nebo vyžádá kompletní načtení parametrů,
nastaví Registr 3011 na hodnotu 0x8000 (bajt 23 = 128, bajt 24 = 0).

Master odpoví postupným zápisem VŠECH TŘÍ bloků parametrů
(270 souvislých registrů: 1001 až 1270) pomocí Modbus FC 16:

Krok 1: LCD nahlásí příznak 0x8000 v odpovědi na periodický dotaz
        [01, 03, 42, 0,0,..., 128,0, ..., RTC, CRC]

Krok 2: Master zapíše Blok 1 (Reg 1001..1090)
        Master -> LCD: [01, 16, 03, E9, 00, 5A, B4, <180 bajtů>, CRC]
        LCD -> Master: [01, 16, 03, E9, 00, 5A, CRC] (Potvrzovací ozvěna)

Krok 3: Master zapíše Blok 2 (Reg 1091..1180)
        Master -> LCD: [01, 16, 04, 43, 00, 5A, B4, <180 bajtů>, CRC]
        LCD -> Master: [01, 16, 04, 43, 00, 5A, CRC] (Potvrzovací ozvěna)

Krok 4: Master zapíše Blok 3 (Reg 1181..1270)
        Master -> LCD: [01, 16, 04, 9D, 00, 5A, B4, <180 bajtů>, CRC]
        LCD -> Master: [01, 16, 04, 9D, 00, 5A, CRC] (Potvrzovací ozvěna)

Krok 5: Master vymaže Registr 3011 zpět na 0
        Master -> LCD: [01, 16, 0B, C3, 00, 01, 02, 00, 00, CRC]
        LCD -> Master: [01, 16, 0B, C3, 00, 01, CRC] (Potvrzovací ozvěna)

Všech 270 konfiguračních parametrů je nyní plně synchronizováno v paměti!

--------------------------------------------------------------------------------
4.6 Komunikace s motory / invertory (Slave 4 a 5)
--------------------------------------------------------------------------------
1. Dotazování na Invertor 1 (Pohon kompresoru):
   Master -> Slave 4: [04, 03, 03, 243, 00, 14, CRC_L, CRC_H]
   Slave 4 -> Master: [04, 03, 28, <28 bajtů dat>, CRC_L, CRC_H]

2. Řízení Invertoru 1 (Příkaz frekvence):
   Master -> Slave 4: [04, 16, 03, ...] (FC 16 zápis cílové frekvence).

3. Dotazování na Invertor 2 (Pohon motoru ventilátoru):
   Master -> Slave 5: [05, 03, 03, 243, 00, 14, CRC_L, CRC_H]
   Slave 5 -> Master: [05, 03, 28, <28 bajtů dat>, CRC_L, CRC_H]

5.2 Bitové pole digitálních výstupů (Relé) (Bajtové offsety 43-44)
--------------------------------------------------------------------------------
Bajtový offset 44 (Dolní bajt LSB / Skupina relé 1):
  Bit 0 (0x01) : Povolení pohonu kompresoru (O01)        [1 = ZAP, 0 = VYP]
  Bit 1 (0x02) : Primární oběhové čerpadlo vody (O02)    [1 = ZAP, 0 = VYP]
  Bit 2 (0x04) : 4cestný reverzační ventil (O03)         [1 = ZAP (Top/Odmraz), 0 = VYP]
  Bit 3 (0x08) : Relé motoru ventilátoru (O04)           [1 = ZAP, 0 = VYP]
  Bit 4 (0x10) : Rezervováno
  Bit 5 (0x20) : Topný kabel vany kondenzátu (O06)       [1 = ZAP, 0 = VYP]
  Bit 6 (0x40) : Topný kabel karteru kompresoru (O07)    [1 = ZAP, 0 = VYP]
  Bit 7 (0x80) : Vstřikovací / sprejový ventil (O08)     [1 = ZAP, 0 = VYP]

Bajtový offset 43 (Horní bajt MSB / Skupina relé 2):
  Bit 0 (0x01) : Pomocný záložní elektrokotel (O09)      [1 = ZAP, 0 = VYP]
  Bit 1 (0x02) : Rezervováno
  Bit 2 (0x04) : Výstupní signál souhrnného alarmu (O11) [1 = ALARM, 0 = OK]
  Bit 3 (0x08) : Cirkulační čerpadlo TUV (O12)           [1 = ZAP, 0 = VYP]
  Bit 4 (0x10) : 3cestný přepínací ventil TUV/Top (O13)  [1 = TUV, 0 = Topení]
  Bit 5..7     : Rezervováno

--------------------------------------------------------------------------------
5.3 Digitální vstupy a bezpečnostní spínače (Reg 2034) & Registr alarmu (Reg 2085)
--------------------------------------------------------------------------------
[DŮLEŽITÁ OPRAVA PROTOKOLU]:
Původní analýza telemetrie předpokládala, že fyzické spínače S01..S08 sídlí v
Registru 2085 (bajtový offset 176). Oficiální servisní manuál Nordline N8A
(strany 28-29, 37) jednoznačně potvrzuje, že hardwarové bezpečnostní spínače
sídlí v Registru 2034 (offsety 73-74, kde bajt 74 je LSB), zatímco Registr 2085
nese aktivní číselný kód chyby / ID alarmu.

Bitové pole Registru 2034 (Hardwarové digitální vstupy / Bezpečnostní spínače S01..S07):
Bajtový offset 74 (Registr 2034 dolní bajt / LSB):
  Bit 0 (0x01 / 2034/0) : Spínač vysokého tlaku (S01 / AI/DI 23)   [0 = Sepnuto/OK, 1 = Rozepnuto/Chyba]
  Bit 1 (0x02 / 2034/1) : Spínač nízkého tlaku (S02 / AI/DI 24)    [0 = Sepnuto/OK, 1 = Rozepnuto/Chyba]
  Bit 2 (0x04 / 2034/2) : Průtokový spínač vody (S03 / AI/DI 25)   [0 = Sepnuto/Průtok OK, 1 = Bez průtoku]
  Bit 3 (0x08 / 2034/3) : Nouzový / dálkový spínač (S04 / AI/DI 26)[0 = Sepnuto/Chod, 1 = Rozepnuto/Stop]
  Bit 4 (0x10 / 2034/4) : Přepínač režimu (S05 / AI/DI 27)         [0 = Sepnuto/Topení, 1 = Rozepnuto/Chl]
  Bit 5 (0x20 / 2034/5) : Rezervováno (S06)
  Bit 6 (0x40 / 2034/6) : Ochrana přetížení el.dohřevu(S07/AI/DI29)[0 = Sepnuto/OK, 1 = Rozepnuto/Chyba]
  Bit 7 (0x80 / 2034/7) : Rezervováno (S08)

Bajtový offset 73 (Registr 2034 horní bajt / MSB):
  Bity 8..15            : Interní stavové binární příznaky řídicí desky.

Registr aktivního kódu poruchy (Registr 2085 / Bajtové offsety 175-176):
  Nese aktivní číselný kód chyby nebo ochrany při výskytu alarmu.
  Offset 175 (MSB) : Kategorie alarmu / dílčí kód
  Offset 176 (LSB) : Identifikační kód chyby (Mapováno na chybové kódy v sekci 5.9:
                     např. E11 = Vysoký tlak, E12 = Nízký tlak, E032 = Průtok, F01..F26 = Invertor).

5.4 Struktura rámce dotazování LCD displeje (Reg 3001..3021)
--------------------------------------------------------------------------------
Celková délka odpovědního bufferu = 47 bajtů (Záhlaví 3 bajty + 42 datových bajtů + 2 CRC bajty).

Doporučení pro implementaci v uživatelském rozhraní:
1. Rozdělená architektura plánovače tichého režimu:
   - Čas zahájení (HH:MM) je rozdělen mezi dva Modbus bloky:
     * Hodina: Registr 1069 (Blok nastavení 1, Příznak 0x0002)
     * Minuta: Registr 1261 (Blok nastavení 3, Příznak 0x0008)
   - Čas ukončení (HH:MM) je rozdělen mezi dva Modbus bloky:
     * Hodina: Registr 1070 (Blok nastavení 1, Příznak 0x0002)
     * Minuta: Registr 1262 (Blok nastavení 3, Příznak 0x0008)
   - Uživatelské rozhraní může nabídnout jednotný prvek výběru času HH:MM tím, že
     zapíše příslušné hodnoty do obou registrů.

2. Denní časovače 1 a 2:
   - Časovač 1 (Auto-ZAP) i Časovač 2 (Auto-VYP) se nacházejí výhradně v Bloku 3 (Příznak 0x0008).
   - Změna stavu zapnutí nebo času vyvolá pouze jeden synchronizační handshake s příznakem 8.

3. Stav napájení a přepínání režimu:
   - Stav (1011) i Režim (1012) sídlí v Bloku nastavení 1 (Příznak 0x0002).
   - Při zapnutí/vypnutí čerpadla nebo změně režimu z Home Assistant odešlete Masteru Příznak 2.

4. Řízení oběhového čerpadla vody:
   - Sídlí v Bloku nastavení 2 (Příznak 0x0004) - Reg 1167 (Režim), Reg 1168 (Interval), Reg 1169 (Doba běhu).

5.9 KOMPLETNÍ MATICE CHYBOVÝCH KÓDŮ A ALARMŮ (DLE MANUÁLU)
================================================================================
Při sepnutí bezpečnostní ochrany nebo poruše komponenty hlavní deska čerpadla
zaregistruje alarm. Alarm se zobrazí na fyzickém LCD displeji, uloží do historie
poruch (obrazovka "Failure Logging", přístup 066 / 022), vysílá se přes telemetrii
(Registr 2085 a bitové pole Registru 2034) a spíná relé souhrnného alarmu RO11
(Registr 2019 Bit 10).

6.2 Automatická synchronizace při startu (Flag 128) a ochrana proti zápisu
--------------------------------------------------------------------------------
Aby se zabránilo přepsání nastavení tepelného čerpadla prázdnými nebo nulovými výchozími hodnotami:

1. Automatické vyčtení při spuštění (Flag 128):
   - Při startu Node-RED se do 0,5 s spustí automatický injektážní impulz.
   - Zařadí do fronty Flag 128 (0x8000) a nastaví `lcd_config_initialized = false`.
   - Při nejbližším dotazu odešle Flag 128 Masteru.
   - Master přenese všech 270 skutečných parametrů do paměti Node-RED.
   - Po přijetí závěrečného potvrzení se nastaví `lcd_config_initialized = true`.

2. Ochrana proti neoprávněnému zápisu:
   - Jakýkoliv pokus o změnu registrů (Příznaky 2, 4 nebo 8) je přísně BLOKOVÁN,
     dokud není `lcd_config_initialized === true`.
   - Zablokované požadavky zapíší varování do logu a vrátí chybový objekt:
     `{ error: "CONFIGURATION_NOT_INITIALIZED", message: "..." }`.
   - Po inicializaci slouží živé hodnoty vyčtené při Flag 128 jako základ,
     přičemž se upravují pouze explicitně požadované registry.

--------------------------------------------------------------------------------
6.3 Koexistence na sběrnici a ochrana fyzického LCD (10sekundový watchdog)
--------------------------------------------------------------------------------
Pro zamezení elektrických kolizí transceiverů na sdílené lince RS-485 mezi
fyzickým nástěnným LCD ovladačem (Slave 1) a emulátorem LCD v Node-RED:

1. Problém elektrických kolizí na RS-485:
   - Master periodicky každou ~1 sekundu dotazuje Slave 1 dotazem:
     `[01, 03, 0B, B9, 00, 15]` (FC 03, Reg 3001, Počet 21).
   - Pokud by fyzický LCD ovladač i emulátor v Node-RED zkusily odpovědět současně,
     souběh obou budičů zkreslí napěťové úrovně na vodičích A/B, což způsobí
     chyby rámce (framing errors) a neplatný kontrolní součet CRC.

2. Dynamický mechanismus 10sekundového watchdogu:
   Node-RED implementuje aktivní watchdog mezi uzlem "msg type 01,03,42 Display Reply"
   (ID: `e5329555f3bee408`) a "LCD Emulator (Slave 1 Responder)" (ID: `b1569ee02102ae62`):

   a. Detekce provozu z fyzického LCD:
      - Uzel Display Reply sleduje všechny příchozí pakety ze sběrnice.
      - Když z fyzického LCD dorazí odpověď začínající `[01, 03, 42]`:
        * Okamžitě deaktivuje emulaci: `flow.set("lcd_emulator_enabled", false)`
        * Uloží časové razítko: `flow.set("lcd_display_reply_last_seen", Date.now())`
        * Aktualizuje vizuální stav uzlu: "Real LCD active (Emulation disabled)" (zelená tečka)
        * Restartuje 10sekundový časovač ticha (`setTimeout`) v kontextové paměti.

   b. Spuštění po 10 sekundách ticha (Automatické převzetí řízení):
      - Pokud po dobu 10 sekund nedorazí žádný paket `[01, 03, 42]` (např. fyzický
        displej byl odpojen, vypnut přídavným vypínačem nebo není přítomen):
        * 10sekundový časovač vyprší.
        * Povolí emulaci: `flow.set("lcd_emulator_enabled", true)`
        * Aktualizuje vizuální stav uzlu: "No reply for 10s -> Emulation enabled" (žlutý kroužek)
        * Emulátor LCD plynule převezme odpovídání na dotazy Masteru pro Slave 1.

   c. Okamžité vypnutí při opětovném zapnutí fyzického panelu:
      - Pokud je fyzický displej kdykoliv znovu připojen nebo zapnut vypínačem, hned
        první přijatý paket `[01, 03, 42]` okamžitě deaktivuje emulaci:
        `flow.set("lcd_emulator_enabled", false)`, čímž je zaručena nulová kolize na sběrnici.

3. Dvoustupňová bezpečnostní pojistka v emulátoru (Uzel `b1569ee02102ae62`):
   - Před každou odpovědí na dotaz Masteru zkontroluje emulátor uplynulý čas odmlky:
     ```javascript
     const timeSinceReply = Date.now() - (flow.get("lcd_display_reply_last_seen") || 0);
     if (timeSinceReply < 10000) {
         flow.set("lcd_emulator_enabled", false);
         return null; // Ticho na sběrnici
     }
     ```
   - Ochranná lhůta při startu: Při spuštění nebo nasazení toku je vynucena 10sekundová
     ochranná lhůta ticha (`flow.set("lcd_display_reply_last_seen", Date.now())`),
     aby Node-RED nejprve pasivně vyčkal, zda na sběrnici neodpovídá skutečný displej.
   - Bezpečnost příkazů: Počáteční injektáž Flag 128 (0x8000) pouze připraví požadavek
     do paměti, aniž by předčasně porušila 10sekundové vyhodnocení ticha.

     * `[Temp]`    (Skupina R): např. `[Temp] Diff - R04 Power-on Return Diff`, `[Temp] Curve - R17 Compensation-ON Low AT`
     Entity ID (`object_id`): Generováno jako `hp_<slug>` (např. `number.hp_temp_curve_r17_compensation_on_low_at`).

3. Příklad registrovaného parametru: Reg 1191 (Požadovaná teplota TUV):
   - Registr: 1191 (Blok nastavení 3: 1181..1270).
   - Měřítko: Násobek 10 (`500` = `50.0 °C`).
   - Entita HA: `number.hp_hot_water_setpoint` (komponenta MQTT Number).
   - Jednotka: `°C`, Třída zařízení: `temperature`, Ikona: `mdi:water-boiler`.
   - Rozsah: Min 40.0 °C, Max 65.0 °C, Krok: 0.5 °C, Režim: `box`.
   - Konfigurační téma Discovery: `homeassistant/number/nodered_heatpump_001_reg_1191_boiler_target_temp/config`

4. Sekvence obousměrného zápisu:
   a. Uživatel změní v HA teplotu na 52.0 °C.
   b. HA publikuje "52.0" do `nodered/heatpump/nodered_heatpump_001/config/1191/set`.
   c. Node-RED ověří `flow.get("lcd_config_initialized") === true` (bezpečnostní zámek Flag 128).
   d. Node-RED převede číslo s plovoucí řádovou čárkou na celé číslo: `52.0 / 0.1 = 520`.
   e. Node-RED aktualizuje `lcd_config_registers_block3[1191] = 520` a nastaví `lcd_event_flag = 8`.
   f. Node-RED okamžitě odešle aktualizovaný perzistentní stav `52.0` do `config_state`.
   g. Při nejbližším dotazu Masteru (do 1 s) Slave 1 odpoví s příznakem Flag 8.
   h. Master vyčte Blok 3 (FC 03) nebo zapíše Blok 3 (FC 16), čímž synchronizuje novou žádanou hodnotu.

5. Architektura v Node-RED:
   Uzel "Create HA mqtt device" (`a671a68f7d9c1dfb`) dynamicky generuje veškeré zprávy
   Discovery z polí `sensorMap` a `configRegisterList`, což zajišťuje automatickou synchronizaci entit.

9. PRACOVNÍ POSTUP OBJEVOVÁNÍ PARAMETRŮ (DIFF-LOGGING V BĚŽNÉM PROVOZU)
================================================================================
Pro jednoznačnou identifikaci neznámých konfiguračních registrů je v Node-RED
implementováno pasivní diff-logování:

1. Příprava:
   - Řídicí deska čerpadla i reálný LCD panel běžně komunikují po lince RS-485.
   - Node-RED běží s aktivovaným 10sekundovým watchdogem:
     * Dokud reálný LCD panel odpovídá pakety `[01, 03, 42]`, emulace zůstává
       automaticky VYPNUTÁ, což zaručuje 100% pasivní odposlech bez jakéhokoliv
       rizika kolize na sběrnici.
     * Pokud je reálný LCD panel odpojen na >10 s, Node-RED plynule převezme emulaci.
   - Uzel "Detect & Log Config Register Changes" naslouchá příchozím rámcům.

2. Postup:
   - Při prvním přijatém paketu pro každý blok se v paměti vytvoří výchozí snímek
     (baseline snapshot) zaznamenávající všechny nenulové hodnoty.
   - Přejděte k fyzickému nástěnnému LCD ovladači a změňte JEDINÝ parametr
     (např. změňte cílovou teplotu TUV z 50 °C na 52 °C, nebo sklon topné křivky).
   - Potvrďte a uložte nastavení na LCD ovladači.
   - LCD ovladač odešle aktualizovaný 180bajtový blok dat Masteru.
   - Diff logger porovná 90 registrů s předchozím uloženým snímkem.
   - Do ladicího okna Node-RED i do souboru `/data/log/config_changes.txt` zapíše
     okamžitý řádek s rozdílem hodnot:

     Příklad výstupu:
     2026-10-01 12:50:33 | [CONFIG CHANGED] Block 1 (Reg 1001-1090 / Flag 2) via FC 16 Write [1 change(s)]: Reg 1040: 50 -> 52 (Diff: +2 | Hex: 0x0032->0x0034)

   - Odvozený závěr: Došlo ke změně Registru 1040 (+0,2 °C).
     [Historická poznámka: V rané fázi testování se předpokládalo, že Registr 1040
      je žádaná teplota TUV; porovnání s oficiálním manuálem jednoznačně prokázalo,
      že Registr 1040 je Parametr A01 (Protimrazová teplota, 5.0 °C -> 5.2 °C),
      zatímco žádaná teplota TUV sídlí v Registru 1191 (Parametr R01 v Bloku 3).]

3. Údržba logovacího souboru:
   - Cesta k souboru: `/data/log/config_changes.txt`
   - Pomocí uzlu "delete" v Node-RED můžete logovací soubor kdykoli vymazat.
   - Pomocí injektážního uzlu "Reset diff baseline snapshots" můžete znovu inicializovat
     výchozí snímky parametrů.
