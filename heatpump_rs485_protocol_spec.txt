1. PHYSICAL & LINK LAYER CONFIGURATION
================================================================================
Bus Interface     : RS-485 (2-wire, Half-Duplex, differential A/B)
Device Port (Linux): /dev/ttyUSB-TC (USB-to-RS485 adapter)
Baud Rate         : 9600 bps
Data Bits         : 8
Parity            : None (N)
Stop Bits         : 1
Flow Control      : None
Framing Standard  : Modbus RTU
Byte Order        : Big-Endian (MSB first) for 16-bit register words
CRC Algorithm     : Modbus CRC-16 (Polynomial: 0xA001, Init: 0xFFFF, Low-Byte first)

CRC Calculation in JavaScript (Reference):
------------------------------------------
function calculateCRC(buf, length) {
    let crc = 0xFFFF;
    for (let pos = 0; pos < length; pos++) {
        crc ^= buf[pos];
        for (let i = 8; i !== 0; i--) {
            if ((crc & 0x0001) !== 0) {
                crc = (crc >> 1) ^ 0xA001;
            } else {
                crc >>= 1;
            }
        }
    }
    return crc; // low byte: crc & 0xFF, high byte: (crc >> 8) & 0xFF
}

2. SYSTEM ARCHITECTURE & BUS PARTICIPANTS
================================================================================
The Heat Pump main control board acts as the Modbus MASTER.
All other modules act as Modbus SLAVES.

Device / Slave Addresses:
-------------------------
- Address 0x00 (0)  : Modbus Broadcast (Sent by Master to all units; no slave replies)
- Address 0x01 (1)  : Main Control Panel / LCD Display Module
- Address 0x02 (2)  : Secondary Control Panel / Expansion Display (optional/polled)
- Address 0x04 (4)  : Compressor / Motor Inverter Driver 1
- Address 0x05 (5)  : Fan Motor / Inverter Driver 2

Topology:
---------
  +-----------------------------------------------------------+
  |                   RS-485 Bus (9600 8N1)                   |
  +----+-------------+-----------------+-------------+--------+
       |             |                 |             |
+------+-----+ +-----+------+    +-----+------+ +----+-------+
|  HP Main   | | LCD Display|    | Inverter 1 | | Inverter 2 |
| Controller | |  (Slave 1) |    |  (Slave 4) | |  (Slave 5) |
|  [MASTER]  | +------------+    +------------+ +------------+
+------------+


================================================================================
3. CYCLIC COMMUNICATION OVERVIEW (POLLING CYCLE)
================================================================================
The Master controller runs an active polling loop with an approximate 1-second
repetition rate. The sequence typically looks as follows:

1. Broadcast Status Part A (Addr 0, FC 16, Reg 2001, 90 regs / 180 bytes)
2. Broadcast Status Part B (Addr 0, FC 16, Reg 2091, 90 regs / 180 bytes)
3. Poll LCD Display (Addr 1, FC 03, Reg 3001, 21 regs / 42 bytes)
   -> LCD replies with heartbeat + status/event flag + current real-time clock.
4. If LCD reported an Event/Change Flag in Register 3011:
   - Flag 0x0002 : Trigger Settings Block 1 sync (Reg 1001..1090)
   - Flag 0x0004 : Trigger Settings Block 2 sync (Reg 1091..1180)
   - Flag 0x0008 : Trigger Settings Block 3 sync (Reg 1181..1270)
   - Flag 0x8000 : Full Initialization / Resync (Reg 1001..1270 across all 3 blocks)
   -> Master executes the corresponding parameter synchronization handshake.
5. Poll Secondary Display if configured (Addr 2, FC 03, Reg 3001, 21 regs).
6. Poll Inverter 1 (Addr 4, FC 03, Reg 1011, 14 regs) -> Inverter 1 replies (28 bytes).
7. Command Inverter 1 (Addr 4, FC 16, target frequency).
8. Poll Inverter 2 (Addr 5, FC 03, Reg 1011, 14 regs) -> Inverter 2 replies (28 bytes).

--------------------------------------------------------------------------------
4.1 Master Broadcast Part A (Status & Telemetry)
--------------------------------------------------------------------------------
Direction : Master -> Broadcast (No response expected)
Function  : Modbus FC 16 (0x10) - Write Multiple Registers
Header    : [00, 16, 07, 209, 00, 90, 180] -> [0x00, 0x10, 0x07, 0xD1, 0x00, 0x5A, 0xB4]
            - Slave Address : 0 (Broadcast)
            - Function Code : 16 (0x10)
            - Start Register: 2001 (0x07D1)
            - Reg Count     : 90 (0x005A)
            - Byte Count    : 180 (0xB4)
Payload   : 180 bytes of live telemetry (temperatures, pressures, relays, EVV, electrical).
CRC       : 2 bytes Modbus CRC16.
Total len : 189 bytes.

--------------------------------------------------------------------------------
4.2 Master Broadcast Part B (System Control & Sync)
--------------------------------------------------------------------------------
Direction : Master -> Broadcast (No response expected)
Function  : Modbus FC 16 (0x10) - Write Multiple Registers
Header    : [00, 16, 08, 43, 00, 90, 180] -> [0x00, 0x10, 0x08, 0x2B, 0x00, 0x5A, 0xB4]
            - Slave Address : 0 (Broadcast)
            - Function Code : 16 (0x10)
            - Start Register: 2091 (0x082B)
            - Reg Count     : 90 (0x005A)
            - Byte Count    : 180 (0xB4)
Key Offsets inside full buffer:
- Offset 25 (2 bytes) : Reg 2091 confirmation value
- Offset 33 (2 bytes) : Constant 15 (0x000F)
- Offset 35 (2 bytes) : Constant 738 (0x02E2)
- Offset 37 (2 bytes) : Toggle state (0 or 1), changes every few minutes
- Offset 39 (2 bytes) : Magic synchronization word: 0x5AA5 (23205 dec)

--------------------------------------------------------------------------------
4.3 LCD Display Polling & Heartbeat (Slave 1)
--------------------------------------------------------------------------------
Direction : Master -> Slave 1 (Poll)
Request   : [01, 03, 11, 185, 00, 21, 87, 196] -> [0x01, 0x03, 0x0B, 0xB9, 0x00, 0x15, 0x57, 0xC4]
            - Slave ID      : 1
            - Function Code : 3 (Read Holding Registers)
            - Start Address : 3001 (0x0BB9)
            - Register Qty  : 21 (0x0015)
            - CRC16         : 0x57 0xC4

Direction : Slave 1 -> Master (Response)
Format    : [01, 03, 42, <42 data bytes>, <CRC_LOW>, <CRC_HIGH>] (Total 47 bytes)
            - Slave ID      : 1
            - Function Code : 3
            - Byte Count    : 42 (0x2A = 21 registers * 2)
            - Bytes [3..22] : Control & status registers (Reg 3001..3010). Mostly 0x00.
            - Offset 23-24  : Action / Trigger Register (Reg 3011, Big-Endian word):
                              * 0x0000 = Normal idle / no change.
                              * 0x0002 = Settings Block 1 update trigger (Reg 1001..1090).
                              * 0x0004 = Settings Block 2 update trigger (Reg 1091..1180).
                              * 0x0008 = Settings Block 3 update trigger (Reg 1181..1270).
                              * 0x8000 = Full System Initialization / Resync Trigger (MSB set,
                                         byte 23 = 128 / 0x80, byte 24 = 0).
            - Bytes [35..44]: Current Real-Time Clock (RTC) broadcasted by the LCD display:
                              * Offset 35-36: Year % 100 (e.g. 26 for 2026)
                              * Offset 37-38: Month (1-12)
                              * Offset 39-40: Day of month (1-31)
                              * Offset 41-42: Hour (0-23)
                              * Offset 43-44: Minute (0-59)

--------------------------------------------------------------------------------
4.4 Settings Synchronization Handshake (Display -> Master)
--------------------------------------------------------------------------------
When single setting blocks are modified, Register 3011 notifies the Master:

- Block 1 (Flag 0x0002): Master synchronizes 90 registers at start address 1001 (0x03E9).
- Block 2 (Flag 0x0004): Master synchronizes 90 registers at start address 1091 (0x0443).
- Block 3 (Flag 0x0008): Master synchronizes 90 registers at start address 1181 (0x049D).

Single Block Handshake Flow:
1. LCD sets Flag (0x0002, 0x0004, or 0x0008) in Register 3011 during poll response.
2. Master requests parameters via FC 03 Read OR writes parameters via FC 16 Write.
3. LCD transfers / echoes the 180 bytes of configuration data.
4. Master sends FC 16 to clear Register 3011: [01, 16, 0B, C3, 00, 01, 02, 00, 00, 0D, A3].
5. LCD confirms write with FC 16 Echo: [01, 16, 0B, C3, 00, 01, F3, D1].
Handshake complete; system returns to 1 Hz idle polling.

--------------------------------------------------------------------------------
4.5 Full System Initialization Handshake (Flag 128 / 0x8000 Full Read-Out)
--------------------------------------------------------------------------------
When the LCD controller powers on, reboots, or requests a full parameter read-out,
it sets Register 3011 to 0x8000 (byte 23 = 128, byte 24 = 0).

The Master responds by sequentially transferring ALL THREE parameter blocks
(270 contiguous registers: 1001 to 1270) via Modbus FC 16:

Step 1: LCD reports Flag 0x8000 in periodic poll response
        [01, 03, 42, 0,0,..., 128,0, ..., RTC, CRC]

Step 2: Master writes Block 1 (Reg 1001..1090)
        Master -> LCD: [01, 16, 03, E9, 00, 5A, B4, <180 bytes>, CRC]
        LCD -> Master: [01, 16, 03, E9, 00, 5A, CRC] (Confirmation echo)

Step 3: Master writes Block 2 (Reg 1091..1180)
        Master -> LCD: [01, 16, 04, 43, 00, 5A, B4, <180 bytes>, CRC]
        LCD -> Master: [01, 16, 04, 43, 00, 5A, CRC] (Confirmation echo)

Step 4: Master writes Block 3 (Reg 1181..1270)
        Master -> LCD: [01, 16, 04, 9D, 00, 5A, B4, <180 bytes>, CRC]
        LCD -> Master: [01, 16, 04, 9D, 00, 5A, CRC] (Confirmation echo)

Step 5: Master clears Register 3011 back to 0
        Master -> LCD: [01, 16, 0B, C3, 00, 01, 02, 00, 00, CRC]
        LCD -> Master: [01, 16, 0B, C3, 00, 01, CRC] (Confirmation echo)

All 270 configuration parameters are now fully synchronized into memory!

--------------------------------------------------------------------------------
4.6 Motor / Inverter Communication (Slaves 4 & 5)
--------------------------------------------------------------------------------
1. Polling Inverter 1 (Compressor motor driver):
   Master -> Slave 4: [04, 03, 03, 243, 00, 14, CRC_L, CRC_H]
   Slave 4 -> Master: [04, 03, 28, <28 bytes data>, CRC_L, CRC_H]

2. Controlling Inverter 1 (Frequency command):
   Master -> Slave 4: [04, 16, 03, ...] (FC 16 write targeting frequency setpoint).

3. Polling Inverter 2 (Fan motor driver):
   Master -> Slave 5: [05, 03, 03, 243, 00, 14, CRC_L, CRC_H]
   Slave 5 -> Master: [05, 03, 28, <28 bytes data>, CRC_L, CRC_H]

5.3 Digital Inputs & Safety Switches (Reg 2034) & Alarm Register (Reg 2085)
--------------------------------------------------------------------------------
[CRITICAL PROTOCOL CORRECTION]:
Early telemetry analysis speculated that physical switches S01..S08 resided in
Register 2085 (Byte Offset 176). The official Nordline N8A manufacturer manual
(pages 28-29, 37) conclusively clarifies that the hardware digital safety switches
reside in Register 2034 (Byte Offsets 73-74, where payload byte 67 is LSB), while
Register 2085 carries the active numerical Alarm Code / Fault ID.

Register 2034 Bitfield (Hardware Digital Inputs / Safety Switches S01..S07):
Byte Offset 74 (Register 2034 Lower Byte / LSB):
  Bit 0 (0x01 / 2034/0) : High Pressure Switch (S01 / AI/DI 23)   [0 = Closed/OK, 1 = Open/Trip]
  Bit 1 (0x02 / 2034/1) : Low Pressure Switch (S02 / AI/DI 24)    [0 = Closed/OK, 1 = Open/Trip]
  Bit 2 (0x04 / 2034/2) : Water Flow Switch (S03 / AI/DI 25)      [0 = Closed/Flow OK, 1 = Open/No Flow]
  Bit 3 (0x08 / 2034/3) : Emergency / Remote Switch (S04 / AI/DI 26)[0 = Closed/Run, 1 = Open/Stop]
  Bit 4 (0x10 / 2034/4) : Mode Switch (S05 / AI/DI 27)            [0 = Closed/Heating, 1 = Open/Cooling]
  Bit 5 (0x20 / 2034/5) : Reserved (S06)
  Bit 6 (0x40 / 2034/6) : Heater Overload Switch (S07 / AI/DI 29) [0 = Closed/OK, 1 = Open/Trip]
  Bit 7 (0x80 / 2034/7) : Reserved (S08)

Byte Offset 73 (Register 2034 Upper Byte / MSB):
  Bits 8..15            : Controller internal binary status flags.

Active Fault Register (Register 2085 / Byte Offsets 175-176):
  Carries the active numerical error / protection code when an alarm trips.
  Offset 175 (MSB) : Alarm Category / Sub-code
  Offset 176 (LSB) : Fault Identifier Code (Mapped to Fault Codes in Section 5.9:
                     e.g. E11 = High Pressure, E12 = Low Pressure, E032 = Flow Error, F01..F26 = Inverter).

     * Hour: Register 1070 (Settings Block 1, Flag 0x0002)
     * Minute: Register 1262 (Settings Block 3, Flag 0x0008)

     register writes to their respective Modbus blocks.

2. Daily Timer 1 and Timer 2 Schedules:
   - Timer 1 (Auto-ON) and Timer 2 (Auto-OFF) reside entirely in Settings Block 3 (Flag 0x0008).

   - Both State (1011) and Mode (1012) reside in Settings Block 1 (Flag 0x0002).
   - When turning the heat pump on/off or switching modes from Home Assistant, send Flag 2 to Master.

4. Water Circulation Pump Management:
   - Reside in Settings Block 2 (Flag 0x0004) - Reg 1167 (Mode), Reg 1168 (Interval time), Reg 1169 (Run duration).

6.2 Startup Auto-Sync (Flag 128) & Write Protection Guard
--------------------------------------------------------------------------------
To prevent overwriting heat pump settings with blank, zeroed, or unverified defaults:

1. Automatic Startup Read-out (Flag 128):
   - When Node-RED starts up, an auto-inject fires within 0.5s.
   - It sets Flag 128 (0x8000) and marks lcd_config_initialized = false.
   - On the next poll, Flag 128 is sent to the Master.
   - The Master transfers all 270 real parameter registers into Node-RED memory.
   - Once the final ACK is received, lcd_config_initialized = true is set.

2. Write Protection Guard:
   - Any attempt to modify configuration registers (Flag 2, 4, or 8) is
     strictly BLOCKED until lcd_config_initialized === true.
   - Blocked requests log a warning and return error object:
     { error: "CONFIGURATION_NOT_INITIALIZED", message: "..." }.
   - Once initialized, parameter changes use the live values read during Flag 128
     as the base, modifying only the explicitly requested registers.

--------------------------------------------------------------------------------
6.3 Bus Coexistence & Physical LCD Guard (10-Second Watchdog)
--------------------------------------------------------------------------------
To completely prevent electrical transceiver collisions on the shared RS-485 bus
between the physical LCD wall controller (Slave 1) and the Node-RED LCD Emulator:

1. Electrical Collision Problem on RS-485:
   - The Heat Pump Master periodically polls Slave 1 every ~1 second with:
     [01, 03, 0B, B9, 00, 15] (FC 03, Reg 3001, Qty 21).
   - If both the physical LCD display unit and Node-RED's emulator attempt to respond
     to this poll simultaneously, transceiver contention garbles the frame on the wire,
     causing framing errors and CRC checksum failures.

2. Dynamic 10-Second Watchdog Mechanism:
   Node-RED implements an active watchdog between node "msg type 01,03,42 Display Reply"
   (ID: e5329555f3bee408) and "LCD Emulator (Slave 1 Responder)" (ID: b1569ee02102ae62):

   a. Detection of Physical LCD Traffic:
      - The Display Reply node inspects all incoming bus packets.
      - When a response starting with [01, 03, 42] arrives from the physical LCD:
        * Immediately disables emulation: flow.set("lcd_emulator_enabled", false)
        * Records timestamp: flow.set("lcd_display_reply_last_seen", Date.now())
        * Updates node visual status: "Real LCD active (Emulation disabled)" (green dot)
        * Resets/re-arms a 10-second silence timer (setTimeout) in context memory.

   b. 10-Second Silence Trigger (Automatic Failover):
      - If no [01, 03, 42] reply is received for 10 consecutive seconds (e.g. physical
        display is disconnected, powered down, or absent):
        * The 10-second timer expires.
        * Enables emulation: flow.set("lcd_emulator_enabled", true)
        * Updates node visual status: "No reply for 10s -> Emulation enabled" (yellow ring)
        * The LCD emulator takes over answering Slave 1 polls seamlessly.

   c. Immediate Disabling on Physical Reconnection:
      - If the physical LCD display is reconnected or powered on at any time, the very
        first [01, 03, 42] packet received immediately disables emulation:
        flow.set("lcd_emulator_enabled", false), guaranteeing zero bus contention.

3. Emulator Fail-Safe Dual Guard (Node b1569ee02102ae62):
   - Before replying to any Master poll or processing any Modbus frame, the emulator
     evaluates elapsed silence:
     const timeSinceReply = Date.now() - (flow.get("lcd_display_reply_last_seen") || 0);
     if (timeSinceReply < 10000) {
         flow.set("lcd_emulator_enabled", false);
         return null; // Bus silence
     }
   - Startup Grace Period: On flow boot / deploy, a 10-second silence grace period
     is enforced (flow.set("lcd_display_reply_last_seen", Date.now())) so Node-RED waits
     silently to determine if a physical LCD is present before transmitting.
   - Command Safety: Startup inject ("start_flag_128") queues Flag 128 (0x8000) into
     memory without prematurely overriding the 10-second silence evaluation.

7.2 Bidirectional Home Assistant MQTT Integration for Configuration Registers
--------------------------------------------------------------------------------
For configuration registers (such as target setpoints, limits, and heating curves),
Node-RED provides bidirectional synchronization using Home Assistant MQTT Discovery:

1. Device & Topic Architecture:
   - Device Identifier: `nodered_heatpump_001` (Heat Pump)
   - Configuration State Topic: `nodered/heatpump/nodered_heatpump_001/config_state`

   - Configuration Set Topic: `nodered/heatpump/nodered_heatpump_001/config/<reg>/set`
     * Inbound MQTT topic subscribed by Node-RED.
     * When user changes a parameter in HA, HA publishes the value (e.g. "52.0" or "ON").

2. Home Assistant UI Naming, Grouping & Entity ID Taxonomy:
   To ensure clean logical grouping and alphabetical sorting on Home Assistant device cards:
   - Controls Card (21 primary user controls):
     Clean user names without bracket tags: `Power State`, `Operating Mode`, `Heating Setpoint`,
     `Hot Water Setpoint`, `Cooling Setpoint`, `Timer 1 (ON) Enable`, `Fast Mute (8h)`, etc.
     Entity IDs: `switch.hp_power_state`, `select.hp_operating_mode`, `number.hp_boiler_target_temp`, etc.
   - Configuration Card (88 advanced registers with `entityCategory: "config"`):
     Standardized format: `"[Group] Sub - ID Name"`
     Matching LCD controller display tabs:
     * `[System]`  (Group H): e.g. `[System] General - H01 Auto Start`, `[System] Inverter - H06 Frequency Control P Value`
     * `[Protect]` (Group A): e.g. `[Protect] Antifreeze - A01 Antifreeze Temp`, `[Protect] Limits - A04 Shutdown Ambient Temp`
     * `[Fan]`     (Group F): e.g. `[Fan] Heating - F01 Max Speed in Heating`, `[Fan] Motor - F14 DC/EC Fan Rated Speed`
     * `[Defrost]` (Group D): e.g. `[Defrost] Exit - D01 Exit Defrost Temp`, `[Defrost] Sliding - D05 Sliding High Point LP`
     * `[EEV]`     (Group E): e.g. `[EEV] Mode - E01 Adjustment Mode`, `[EEV] Heat - E02 Superheat in Heating`
     * `[Disinf]`  (Group G): e.g. `[Disinf] Target - G01 Disinfection Setpoint`, `[Disinf] Schedule - G04 Work Cycle`
     * `[Pump]`    (Group P): e.g. `[Pump] Timing - P04 Pump Advanced Start Time`, `[Pump] Manual - P05 Pump Manual-control`
     * `[Temp]`    (Group R): e.g. `[Temp] Diff - R04 Power-on Return Diff`, `[Temp] Curve - R17 Compensation-ON Low AT`
     Entity IDs (`object_id`): Generated cleanly as `hp_<slug>` (e.g. `number.hp_temp_curve_r17_compensation_on_low_at`).

3. Registered Configuration Register Example: Reg 1191 (Hot Water Setpoint):
   - Register: 1191 (Settings Data Block 3: 1181..1270).
   - Scaling: Factor of 10 (`500` = `50.0 °C`).
   - HA Entity: `number.hp_hot_water_setpoint` (MQTT Number component).
   - Unit: `°C`, Device Class: `temperature`, Icon: `mdi:water-boiler`.
   - Range: Min 40.0 °C, Max 65.0 °C, Step: 0.5 °C, Mode: `box`.
   - Discovery Topic: `homeassistant/number/nodered_heatpump_001_reg_1191_boiler_target_temp/config`

4. Bidirectional Write Sequence:
   a. User changes temperature in HA to 52.0 °C.
   b. HA publishes "52.0" to `nodered/heatpump/nodered_heatpump_001/config/1191/set`.
   c. Node-RED verifies `flow.get("lcd_config_initialized") === true` (Flag 128 safety guard).
   d. Node-RED converts float to raw integer: `52.0 / 0.1 = 520`.
   e. Node-RED updates `lcd_config_registers_block3[1191] = 520` and sets `lcd_event_flag = 8`.
   f. Node-RED immediately publishes updated retained state `52.0` to `config_state`.
   g. On the next periodic poll (within 1 sec), Slave 1 responds with Flag 8.
   h. Master reads Block 3 (FC 03) or writes Block 3 (FC 16), synchronizing the new setpoint.

5. Node-RED Architecture:
   The "Create HA mqtt device" node (`a671a68f7d9c1dfb`) builds all discovery payloads dynamically
   from `sensorMap` and `configRegisterList`, ensuring automatic in-place entity synchronization.

9. PARAMETER DISCOVERY WORKFLOW (DIFF-LOGGING IN NORMAL OPERATION)
================================================================================
To deduce what unknown configuration registers represent, passive diff-logging
is implemented in Node-RED:

1. Setup:
   - Heat Pump Master and real LCD panel communicate normally on RS-485.
   - Node-RED runs with automatic 10-second LCD watchdog enabled:
     * As long as the real LCD replies with [01, 03, 42], emulation is kept automatically
       DISABLED, ensuring 100% passive sniffing with zero risk of bus collision.
     * If the real LCD is unplugged for >10s, Node-RED seamlessly assumes emulation.
   - Node "Detect & Log Config Register Changes" listens to incoming frames.

2. Process:
   - On the first packet received for each block, an initial baseline snapshot
     is stored in memory (logging all non-zero values).
   - Go to the physical LCD display wall unit and modify ONE single parameter
     (e.g., change DHW target temperature from 50 °C to 52 °C, or heating curve slope).
   - Save/confirm the setting on the LCD unit.
   - The LCD unit transmits the updated 180-byte block to the Master.
   - The diff logger compares the 90 registers against the previous snapshot.
   - It outputs an instant diff line to both the Node-RED Debug window and to
     file `/data/log/config_changes.txt`:

     Example Output:
     2026-10-01 12:50:33 | [CONFIG CHANGED] Block 1 (Reg 1001-1090 / Flag 2) via FC 16 Write [1 change(s)]: Reg 1040: 50 -> 52 (Diff: +2 | Hex: 0x0032->0x0034)

   - Conclusion deduced: Register 1040 modified (+0.2 °C change).
     [Historical Note: In early testing, Register 1040 was initially hypothesized to be DHW setpoint;
      cross-referencing with the official manufacturer manual conclusively established that Register 1040
      is actually Parameter A01 (Antifreeze Temp, 5.0 °C -> 5.2 °C), while DHW Target Temperature resides
      in Register 1191 (Parameter R01 in Settings Block 3).]

3. Log File Maintenance:
   - File path: `/data/log/config_changes.txt`
   - Use the "delete" inject node in Node-RED to clear the log file at any time.
   - Use the "Reset diff baseline snapshots" inject node to re-initialize baseline.
